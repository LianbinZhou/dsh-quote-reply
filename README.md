# dsh-quote-reply

在 dsh（DeepSeek Harness）的 Web 界面里**划选任意对话文字，浮出「引用 / 复制」小卡片**。

点「引用」，这段原文就以 Markdown 引用块的形式落进输入框的光标处，你接着写问题——模型能直接读到你引的是哪一段。

> 交互抄的是通义千问那套「划词浮条」。dsh 官方没做这个交互，这里补上。

## 它长什么样

1. 用鼠标划选对话里的文字（你的话、AI 的回答、代码块、工具输出都行）
2. 松开鼠标，选区上方浮出一张卡片：`↩ 引用` ｜ `⧉ 复制`
3. 点「引用」，输入框里出现：

   ```
   > 你选中的原文

   （光标停在这里，接着写你的问题）
   ```

4. 点「复制」就是把选中内容进剪贴板，按钮闪一下「已复制」就消失

## 装

零依赖，不需要 `npm install`。

```powershell
git clone https://github.com/LianbinZhou/dsh-quote-reply.git
```

然后用 dsh 的插件安装入口把这个**目录的绝对路径**装成 bundle（Web GUI 的插件设置里选“从本地目录安装”，或者让 dsh 的 Agent 用 `install_bundle` 指向它）。

装完**重启一次 dsh** 最稳。

> 装到哪个 profile，就在哪个 profile 的界面里生效。

## 行为细节

| 情况 | 行为 |
|---|---|
| 划选对话里的文字，松开鼠标 | 浮出卡片 |
| 在**输入框里**划选文字（改错别字、选词） | **不弹**，不打扰你打字 |
| 点别处 / 按 Esc / 页面滚动 / 右键 | 卡片自动收起 |
| 卡片已经开着时点右键 | 卡片先让开，系统的右键菜单正常出现（dsh 自带的「复制」不受影响） |
| 引用多行文字 | 每行都加 `> `，整段仍是一个引用块；连续空行会被压成一个 |
| 浅色 / 深色主题 | 跟着 dsh 的主题走，颜色全部取自 `--dsw-alias-*` 主题变量 |

## 已知限制

- **引用是纯文本进输入框**，不是钉在输入框上方的那种单行小卡片。选一段长文时输入框里会比较长。
  这是刻意的第一版取舍：dsh 内部那套“引用胶囊”（`@文件` 用的机制）没有公开的注册接口，硬做要逆向内部 API，容易随版本升级失效。
- **空白会话**（还没进入任何会话、输入框是灰的）时点「引用」，因为没地方落笔，会退化成“复制到剪贴板”。
- 只处理**左键划选**。右键不弹卡片（右键是系统的地盘）。

## 它是怎么接进 dsh 的

浏览器侧的实现挂在两个 slot 上：

| Slot | 作用域 | 干的事 |
|---|---|---|
| `shell.overlay` | root | 浮层菜单。监听 `mouseup`，读 `window.getSelection()`，自己画卡片 |
| `conversation.input.dock` | session | 收口。菜单层拿不到 `inputActions`（那是 session 作用域的 props），所以两层通过模块内的一个小注册表交接，由 sink 调 `inputActions.captureInsertion()` + `insertText()` 把引用写进草稿 |

写草稿失败时（比如草稿版本变了）退化为 `setDraft(现有草稿 + 引用)`。

**这个插件不发送任何模型请求、不写任何会话事件、不读别的插件的 DOM。** 引用只是普通文本，跟着你按发送键走正常流程。

| 文件 | 说明 |
